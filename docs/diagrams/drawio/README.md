# Нативные диаграммы draw.io — лабораторные №1–3

Файлы `.drawio` содержат **несжатый XML**, редактируемые узлы и направленные связи `mxCell`. Встроенных изображений, SVG-снимков и Mermaid-кода нет. Открытие: **diagrams.net / draw.io → Файл → Открыть с устройства**. Страницы переключаются вкладками снизу. Сохранять следует в формате `.drawio`, а не экспортировать в картинку.

## Сохранённая семантика

- Перенесены все узлы, связи, подписи, направления и принадлежность C4-границам; ничего не объединено, не удалено и не добавлено в модель. Заголовки, легенды и две линии каждого DFD-хранилища — оформление, а не новые компоненты или потоки.
- C4 охватывает **только Context, Container и Component**, без уровня Code. Границы — настоящие родительские `mxCell` с вложенными узлами. Компоненты функций и DTO не превращены в классы. «Расчёт и обогащение» остаётся логическими участками handler, что явно написано внутри узла.
- C4-граница обозначает логическую область, **не гарантию сетевой изоляции**. Прямой вызов опубликованных портов сервисов без проверки JWT сохранён.
- DFD Йордана—Кода: процессы — круги, внешние сущности — прямоугольники. Каждое хранилище состоит из подписанного родительского узла и **двух нативных горизонтальных линий с открытыми боками**. Это не `lined-rectangle`, не закрытый прямоугольник и не картинка. Линии и подпись редактируются; потоки привязаны к родительскому узлу хранилища.
- Каждый запрос и ответ — отдельная именованная стрелка. MGET, SETEX, TTL, чтение PostgreSQL при промахе/невалидном профиле и PG fallback сохранены. Lab2 не содержит Redis/Elasticsearch, lab3 не содержит Elasticsearch.
- Использована одобренная светлая палитра diagram-design: бумага `#f5f5f5`, основной текст `#2d3142`, акцент `#bf4520`; шрифт Arial для русских подписей. Широкие страницы рассчитаны на масштабирование и прокрутку, а не на уменьшение всего документа до ширины телефона.
- Все пути ортогональны, порты разнесены. Для пересечений включены нативные переходы `jumpStyle=arc`. Подписи имеют непрозрачный фон, отдельные коридоры и отступ от линии. Их текст редактируется как подпись соответствующей связи.

## Реально выполненные проверки

Проверки запускались по сохранённым файлам, а не только по подготовленной модели:

1. XML разбирается стандартным `xml.etree.ElementTree`; внутри каждой `diagram` находится `mxGraphModel`, а не сжатая строка. Проверено распределение страниц **5 / 4 / 5**.
2. ID уникальны на каждой странице, `source`, `target` и `parent` разрешаются. Смысловые ID дополнительно имеют уникальные префиксы страниц; стандартные служебные `0` и `1` локальны каждой странице.
3. Полный набор смысловых узлов и связей совпадает с результатом `mermaid_extract.py` для каждого исходника. Проверены направления и тексты всех узлов/связей с нормализацией только HTML и пробелов/переносов строк.
4. Проверены ортогональность заданных путей, отдельные точки подключения, отсутствие прохода путей через посторонние узлы, отсутствие наложений рассчитанных прямоугольников подписей друг на друга и на узлы. Это геометрические проверки подготовленных маршрутов; финальные метрики шрифта и обработка маршрутов редактором требуют визуального просмотра.
5. У каждого DFD-хранилища проверено наличие ровно двух дочерних нативных линий, открытые бока и отсутствие embedded image/SVG.
6. `drawio_extract.py --page all --json` успешно прочитал все три документа: **exit 0** для каждого; на всех 14 страницах **edges_dangling=0**. Числа прочитанных связей по вкладкам: lab1 `2, 8, 5, 19, 19`; lab2 `2, 6, 5, 14`; lab3 `2, 7, 7, 17, 21`.
7. SHA-256 всех исходных файлов каталога `docs/diagrams` до и после генерации совпали. Mermaid-файлы и исходный README не изменены. Код, ZIP, git, контейнеры и данные БД не изменялись.
